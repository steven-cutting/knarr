# 05: CI

**Context:** This adapts libpawdoku's T04. CI runs the same `just` recipes as a contributor's machine, from the same pixi lock decided in 01.

**What to build:** Every pull request and every push to `main` runs the gate in GitHub Actions. One aggregate `check` job turns green only when every gate job passes, and it is the only required check. A separate, non-required audit workflow runs on a schedule.

**Non-goals:** The kind smoke job (13). Renovate and image scanning (27). Release workflows (28).

**Blocked by:** 03, 04

**MVP critical path:** yes. The walking skeleton (13) adds its smoke job here.

**Status:** ready-for-agent

- [ ] A composite setup action installs pixi at the version pinned in 01, installs the lock without changing it, and caches the environment keyed on the lock.
- [ ] The gate jobs call `just` recipes only, with no restated tool invocations in YAML.
- [ ] An aggregate `check` job needs every gate job and fails if any of them fails or is skipped.
- [ ] **Authorization required:** `check` is added as the only required status check on `main`.
- [ ] Every action is pinned to a full commit SHA with a version comment. Workflow permissions start at none and are raised per job only where needed. Concurrency cancels superseded pull-request runs.
- [ ] `actionlint` covers the workflows inside `just check`.
- [ ] The non-required audit workflow runs on a schedule and on manual dispatch. It covers at least the external link check and anything 01 or 02 deferred to it. 27 extends it.
- [ ] A pull request shows a green `check`.
