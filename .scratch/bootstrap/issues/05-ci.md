# 05: CI

**Context:** This adapts libpawdoku's T04. CI runs the same `just` recipes as a contributor's machine, from the same pixi lock decided in 01.

**What to build:** Every pull request and every push to `main` runs the gate in GitHub Actions. One aggregate `check` job turns green only when every gate job passes, and it is the only required check. A separate, non-required audit workflow runs on a schedule.

**Non-goals:** The kind smoke job (13). Renovate and image scanning (27). Release workflows (28).

**Blocked by:** 03, 04

**MVP critical path:** yes. The walking skeleton (13) adds its smoke job here.

**Status:** implemented and verified; required-check authorization pending

- [x] A composite setup action installs pixi at the version pinned in 01, installs the lock without changing it, and caches the environment keyed on the lock.
- [x] The gate jobs call `just` recipes only, with no restated tool invocations in YAML.
- [x] An aggregate `check` job needs every gate job and fails if any of them fails or is skipped.
- [ ] **Authorization required:** `check` is added as the only required status check on `main`.
- [x] Every action is pinned to a full commit SHA with a version comment. Workflow permissions start at none and are raised per job only where needed. Concurrency cancels superseded pull-request runs.
- [x] `actionlint` covers the workflows inside `just check`.
- [x] The non-required audit workflow runs on a schedule and on manual dispatch. It covers at least the external link check and anything 01 or 02 deferred to it. 27 extends it.
- [x] A pull request shows a green `check`.

## Implementation

[PR #5](https://github.com/steven-cutting/knarr/pull/5) adds the shared
[setup action](../../../.github/actions/setup/action.yml) and
[CI workflow](../../../.github/workflows/ci.yml). Setup retains setup-pixi
v0.10.2 at its verified commit SHA, pins pixi v0.81.0, installs with
`locked: true`, and caches by platform and lock hash. Both workflows use it;
CI runs `just check` and the audit runs `just links-audit`. Tickets 01 and 02
leave no additional scheduled audit checks.

The aggregate runs with `always()` and rejects failed, cancelled, or skipped
jobs. Ticket 13 must add its smoke job to `check.needs`. The audit is excluded.
Permissions start at none; checkout jobs receive only `contents: read`.

Validation: actionlint, the Gleam build with warnings as errors, and full
`just check` passed locally (185 Python tests and one Gleam test). Taplo
required a run outside the macOS sandbox. Direct diff review found no further
issues; the requested code-review skill was unavailable.

The gate initially found an existing Decision 0008 documentation failure.
Its manifest registration, decision-index link, and feature-predicate metadata
are repaired; its decision text is unchanged.

`main` currently has no required status checks. After authorization, set its
required status checks to only `check`, preserving the other protection settings.

[Linux CI run](https://github.com/steven-cutting/knarr/actions/runs/37719141831)
passed both the repository gate and aggregate `check` on PR #5.
